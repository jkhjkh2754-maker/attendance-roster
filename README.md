# 경희의 출석부

[웹앱 열기](https://jkhjkh2754-maker.github.io/attendance-roster/)

브라우저에서 제목·인원·명단을 설정하고 한글 출석부 PDF를 만드는 정적 웹앱입니다. 별도의 서버, 데이터베이스, AI API, 로그인 없이 작동합니다.

## 기본 출석부

- 제목, 전체 인원(1~300명), 시작 번호, 날짜(최대 31칸)·회차(최대 40칸)를 지정합니다.
- 연도와 월을 지정하면 요일을 자동으로 넣을 수 있습니다.
- A4 세로·가로, 페이지당 인원(5~40명), 색상, 학번·비고 칸을 선택합니다.
- 한 줄당 `0011 홍길동`, `0011, 홍길동` 또는 이름만 입력합니다. 엑셀의 두 열을 복사한 탭 구분 입력도 지원합니다.
- 입력 순서와 학번 앞자리 0을 보존합니다. 정원 초과·잘못된 명단은 오류로 안내하며 임의로 자르지 않습니다.
- 명단 없이 빈 양식을 생성할 수 있습니다. 설정 변경 후 업데이트 또는 PDF 저장을 누르세요.

## 나의 PDF·이미지 양식

1. PDF 또는 PNG·JPG·WebP 이미지 양식(10MB 이하)을 불러옵니다. PDF는 최대 15쪽을 지원합니다. 이미지는 가로세로 비율을 유지해 PDF 1쪽으로 변환합니다. 이미지의 긴 변은 PDF에서 841.89pt로 설정하며, 3000픽셀을 넘으면 축소합니다. 4천만 화소를 초과하는 이미지는 크기를 줄여 주세요. JPEG 방향 정보와 투명 배경을 처리하며, 투명 부분은 흰색이 됩니다. HEIC·GIF·SVG는 지원하지 않습니다.
2. 이름 칸 버튼을 누른 뒤 미리보기에서 **첫 번째 사람의 칸** 왼쪽 위와 오른쪽 아래를 차례로 누릅니다.
3. 학번이 있다면 학번 칸도 같은 방식으로 지정합니다. 번호 칸은 원본에 번호가 없는 경우에만 지정합니다.
4. 원본의 첫 행과 다음 행의 간격을 pt 단위로 입력합니다. 처음 지정한 칸 높이와 행 간격은 별개입니다. 예덕반 원본은 24행, 행 간격 30pt입니다.
5. 페이지당 인원을 원본 행 수로 맞추고 미리보기를 업데이트합니다. 행 위치가 어긋나면 행 간격을 조절하거나 영역을 다시 지정합니다.
6. 제목을 바꾸려면 제목 영역을 별도로 지정합니다. 선택한 영역만 흰색으로 덮고 새 제목을 넣으므로 테두리와 겹치지 않도록 지정합니다.

### 학번 칸이 없는 양식에 새 칸 추가

1. 양식을 불러온 뒤 **＋ 학번 칸 새로 추가**를 누릅니다.
2. 첫 페이지의 빈 공간에서 **첫 사람의 학번 칸 하나 또는 제목을 제외한 학번 열 전체**를 드래그합니다. 위쪽에는 같은 높이의 ‘학번’ 제목 칸이 들어갈 공간을 남겨 주세요.
3. 첫 칸 높이에 맞춰 해당 학번 영역의 행 간격을 자동 설정합니다. 기존 이름 행과 일치하도록 행 간격과 페이지당 인원을 확인합니다.
4. **선택 영역 편집**에서 위치·너비·높이(%), 글자 크기(pt), 정렬, 행별 테두리와 학번 제목 칸을 조절합니다. 영역을 끌어 이동하거나 오른쪽 아래 모서리를 끌어 크기를 바꿀 수도 있습니다. 기존 이름·번호·제목 영역도 편집하고 삭제할 수 있습니다.
5. 학번과 이름을 입력하고 **미리보기 업데이트 → PDF 저장**을 누릅니다. 명단의 순서와 학번 앞자리 0을 유지하며, 새 테두리와 학번 제목도 PDF에 포함합니다. 빈 명단이면 빈 칸만 만듭니다.

**열 전체 선택 지원:** 먼저 페이지당 인원을 원본 행 수로 맞춥니다. ‘선택할 범위’에서 자동 구분·첫 사람의 한 칸·열 전체를 고를 수 있습니다. 자동 구분은 용지 높이의 15%를 넘는 영역을 열 전체로 보고 페이지당 인원으로 높이를 나눕니다. 이름·학번·번호에 적용하며 제목은 나누지 않습니다. 열 전체에는 제목 행을 포함하지 마세요. 이미 열 전체를 한 칸으로 지정했다면 영역 편집의 ‘선택 영역을 전체 열로 나누기’를 한 번 눌러 높이와 행 간격을 바로잡습니다. 수정된 영역을 다시 나누지 마세요.

새 학번 영역은 한 개를 지원하며 다시 추가하면 기존 학번 영역을 교체합니다. 원본 위에 칸을 덧그리는 방식이므로 기존 표를 자동으로 이동하거나 새 열을 끼워 넣지는 않습니다. 빈 공간이 부족하면 여백이 있는 양식을 사용하세요. 용지 밖으로 나가는 제목·마지막 행은 오류로 안내합니다. 새로고침하면 추가 영역도 사라지므로 PDF를 저장해 주세요.

이 기능은 브라우저 내부에서 처리하며 AI API·서버 업로드·추가 유료 서비스를 사용하지 않습니다.

첨부 양식은 표·날짜·기존 번호를 유지하고 지정한 칸에만 텍스트를 추가합니다. 기본 설정의 색상·용지 방향·날짜 칸 수·비고 칸은 첨부 양식을 재구성하지 않습니다. 여러 페이지의 양식에는 같은 상대 위치를 적용하므로 구조가 같은 페이지를 사용하세요. 추가 페이지가 필요하면 원본 페이지 순서대로 반복합니다. 원본 페이지 수는 줄이지 않습니다.

암호화된 파일, 페이지 회전이나 잘라내기 정보가 있는 PDF는 지원하지 않습니다. PDF로 인쇄하여 일반 페이지로 저장한 뒤 다시 불러오세요. 전자서명된 문서에는 사용하지 마세요. 기입 위치는 사용자가 미리보기로 확인해야 합니다. 저장되는 PDF에는 위치 지정용 초록색 영역 표시가 포함되지 않습니다.

## 개인정보와 비용

- 명단과 첨부 PDF는 브라우저 메모리에서만 처리합니다. 서버 업로드·분석·자동 저장·쿠키·사용자 추적 기능이 없습니다.
- 새로고침하면 입력과 첨부 자료가 사라집니다. 결과는 PDF로 직접 저장하세요.
- 코드·한글 글꼴·라이브러리만 GitHub Pages에서 내려받습니다. GitHub의 일반 접속 로그는 GitHub 정책을 따릅니다.
- 공개 저장소에는 **실제 학생 명단이나 완성 출석부를 올리지 마세요.** 공개 저장소와 공개 페이지는 누구나 접근할 수 있으며, 이 웹앱에는 20명만 접근하도록 제한하는 기능이 없습니다.
- 공개 GitHub 저장소 + GitHub Pages 기본 주소를 사용하며, AI API 호출이 없어 해당 API 비용이 발생하지 않습니다. 유료 도메인·유료 호스팅을 따로 연결하면 그 서비스 비용은 별개입니다.

## 실행 및 배포

빌드 단계가 없습니다. 저장소의 `main` 브랜치 루트를 GitHub Pages 게시 소스로 선택합니다. 웹앱은 HTTPS에서 실행하세요. 파일을 직접 여는 `file://` 실행은 지원하지 않습니다.

로컬 확인: 이 폴더에서 정적 HTTP 서버를 실행하고 브라우저로 접속합니다. 예: `python -m http.server 8080`.

최신 Chrome·Edge·Safari·Firefox를 대상으로 합니다. 모바일에서는 PDF 저장 버튼으로 다운로드 후 파일 앱이나 PDF 뷰어에서 인쇄하세요. 첨부 PDF의 비표준 용지·혼합 방향은 저장한 PDF의 뷰어에서 인쇄하는 편이 정확합니다.

## 검색엔진 등록

사이트 이름은 **경희의 출석부**입니다. HTML 제목·본문·설명·Open Graph·구조화 데이터에 이름을 반영하고, 버전 쿼리(`?v=...`)가 없는 주소를 대표 URL로 지정했습니다. 검색 로봇은 JavaScript 실행 없이도 이름과 설명을 읽을 수 있습니다.

- 대표 URL: https://jkhjkh2754-maker.github.io/attendance-roster/
- 사이트맵: https://jkhjkh2754-maker.github.io/attendance-roster/sitemap.xml

검색엔진의 발견과 수집을 요청하려면 사이트 소유자 계정으로 아래 절차를 진행합니다. 코드 배포만으로 검색 결과 노출이나 순위가 보장되지는 않으며, 수집·색인에는 시간이 걸릴 수 있습니다.

1. [Google Search Console](https://search.google.com/search-console/)에서 위 대표 URL을 **URL 접두어 속성**으로 추가합니다. HTML 파일 또는 HTML 메타 태그 방식으로 소유권을 확인합니다. GitHub Pages 기본 도메인은 직접 DNS를 관리할 수 없으므로 도메인 속성 대신 URL 접두어 속성을 사용합니다.
2. Google Search Console의 **Sitemaps**에서 위 사이트맵 주소를 제출하고, **URL 검사**에서 대표 URL의 색인 생성을 요청합니다.
3. [네이버 서치어드바이저](https://searchadvisor.naver.com/)의 웹마스터 도구에서 사이트를 추가하고, 제공되는 HTML 파일 또는 메타 태그로 소유권을 확인합니다. **요청 → 사이트맵 제출**에 위 사이트맵 주소를 입력하고 **웹 페이지 수집**에서 대표 URL의 수집을 요청합니다.

소유권 확인용 파일·태그는 각 서비스가 실제로 발급한 값을 사용하며, 확인 후에도 유지합니다. 사이트 주소가 바뀌면 `index.html`의 canonical·Open Graph·JSON-LD URL과 `sitemap.xml`도 함께 변경합니다.

### IndexNow로 페이지 갱신 알리기

네이버·Bing 등 IndexNow 참여 검색엔진에는 계정 로그인 없이도 페이지 갱신을 알릴 수 있습니다. 저장소 루트의 **32자리 16진수 이름을 가진 `.txt` 파일**이 이 사이트의 IndexNow 인증 파일입니다. 파일 내용은 확장자를 제외한 파일명과 같으며, 배포 후에도 유지합니다. 이 파일은 Google·네이버 웹마스터 도구의 계정 소유확인용 태그를 대신하지 않습니다.

[네이버 공식 요청 안내](https://searchadvisor.naver.com/guide/indexnow-request)에 따라 `https://searchadvisor.naver.com/indexnow`로 대표 URL과 key, 인증 파일의 공개 주소인 keyLocation을 전송합니다. 이 사이트는 GitHub Pages의 하위 경로이므로 keyLocation에 `https://jkhjkh2754-maker.github.io/attendance-roster/인증파일명.txt`를 반드시 지정합니다. 이 키는 `/attendance-roster/` 아래 URL에만 사용합니다. IndexNow 참여 검색엔진은 접수된 URL을 서로 공유하므로 같은 URL을 여러 엔진에 반복 제출할 필요는 없습니다.

HTTP 200은 요청 접수 성공, 202는 요청 접수 후 키 확인 중이라는 뜻입니다. 어느 응답도 실제 색인이나 검색 노출을 보장하지 않습니다. Google Search Console의 수집 요청은 위의 계정 소유권 확인 절차를 별도로 따릅니다.

`robots.txt`는 호스트 루트인 `https://jkhjkh2754-maker.github.io/robots.txt`에 있을 때만 적용됩니다. 이 프로젝트 경로 아래에 만드는 `attendance-roster/robots.txt`는 검색 로봇 정책으로 사용되지 않습니다. 호스트 루트의 `robots.txt`가 404인 것은 수집 차단이 아니며, 이 사이트는 HTML의 `index, follow`로 색인을 허용합니다. 이후 호스트 루트 정책을 추가할 때 이 사이트 경로를 차단하지 않도록 확인하세요.

## 기능 검증

Playwright와 Chromium이 설치된 환경에서 로컬 HTTP 서버를 8080 포트로 실행한 뒤 `node tests/added-areas.cjs`를 실행합니다. `CHROMIUM_PATH`로 Chromium 실행 파일 경로를 바꿀 수 있습니다. 테스트는 가상 명단과 임시 양식만 사용하며 PDF·이미지 첨부, 새 학번 칸 생성·이동·크기 조절, 정렬·글자 크기, 다중 페이지 명단, 오류 안내, 삭제, 모바일 터치와 외부 요청이 없는지 검증합니다.

### 열별 행 간격과 용지 경계 안내

열 전체로 지정한 이름·학번·번호와 새 학번 칸은 각각 계산한 행 간격을 유지하며, 기본 행 간격을 덮어쓰지 않습니다. 다른 열을 지정해도 기존 열의 간격을 바꾸지 않습니다. 선택 영역 편집의 ‘이 영역의 행 간격’으로 조절하거나 값을 비워 기본 행 간격을 사용할 수 있습니다. PDF 생성 전 아직 나누지 않은 긴 이름·번호 영역도 자동 보정합니다. 명시적으로 ‘첫 사람의 한 칸’을 선택한 영역과 제목은 자동으로 나누지 않습니다. 실제로 용지 밖으로 나가는 경우에는 항목명·페이지·행 번호·적용 간격을 안내하며 명단을 잘라내지 않습니다.
